# crop-fusion-bench

Image + greenhouse-sensor fusion for crop-disease diagnosis, a parameter-matched
variational quantum circuit (VQC) head, and a corruption-robustness study on the
DACON LG Crop Disease Diagnosis data (25 crop × disease × stage classes,
57,673 samples). The first finding is about the benchmark itself: the standard
split leaks recording sessions, and a lookup table on the sensor log nearly
matches the trained sensor model.

[![Tests](https://github.com/thinkiamparanoid2/crop-fusion-bench/actions/workflows/tests.yml/badge.svg)](https://github.com/thinkiamparanoid2/crop-fusion-bench/actions/workflows/tests.yml)

> **Status: work in progress (October 2026).** Every model result below comes
> from the thesis's random stratified split, which leaks recording sessions
> (next section). A session-grouped rerun is the next step. Until it lands, read
> the model numbers as upper bounds and the comparisons between them as
> provisional.

## Session leakage audit

Each DACON sample pairs a photo with the greenhouse sensor log recorded around
it. Photos taken during one recording share that log byte for byte, so they show
the same plants under the same conditions. [`scripts/session_audit.py`](scripts/session_audit.py)
keys every sample by a hash of its raw sensor log
([`audit/session_keys.csv`](audit/session_keys.csv)) and checks the split in
[`Data/`](Data):

| Split | Samples | Share a session with train | Session-lookup accuracy |
|---|---|---|---|
| val | 5,193 | 98.3% | 93.8% |
| test | 5,767 | 98.4% | 94.0% |

The 57,673 samples come from 1,755 recording sessions, and 96% of training
sessions contain a single label. **Session lookup**, which predicts the majority
training label of the sample's session with no learning at all, scores 94.0%
test accuracy. The trained sensor-only model E1 scores 94.4%.

What follows from that, before any grouped-split rerun:

- E1 is mostly identifying the session, not reading the crop's environment.
- Fusion's robustness to corrupted images (below) may come from the sensor
  branch recognizing the session. Its robustness to corrupted sensors may come
  from the photo being a near-duplicate of training photos.
- The image models face the same issue: their test photos have near-twins in
  training.

Keying sessions by recording window instead of the exact log gives 98.4%
(val) and 98.5% (test) overlap.

## Results on the random split

Generated by `python scripts/make_tables.py` from the saved metrics files.

| Model | Inputs | Test macro-F1 | Test accuracy | Test ECE |
|---|---|---|---|---|
| E0 MobileNetV3-Large | image | 0.964 | 0.982 | 0.008 |
| E1 MLP | sensor | 0.883 | 0.944 | 0.017 |
| E2 fusion MLP (canonical) | image + sensor | 0.968 | 0.987 | 0.007 |
| E2-matched-8 (classical head) | image + sensor | 0.973 | 0.988 | 0.248 |
| E3-8 VQC (8-qubit head) | image + sensor | 0.944 | 0.974 | 0.118 |

E2-matched-8 and E3-8 share the frozen encoders and the projection to an
8-dimensional bottleneck, and both have 173,737 trainable parameters. They
differ only in the 64-parameter decision layer: classical or quantum circuit.

- **The VQC head does not improve accuracy.** It is 0.029 macro-F1 below its
  matched classical head.
- **Its calibration gain is relative to a poorly calibrated comparator.** ECE
  0.118 vs 0.248 for E2-matched-8, while the unconstrained E2 fusion head sits at
  0.007. No calibration advantage over classical fusion is claimed.

Corruption robustness: macro-F1 drop from clean to corrupted test inputs.
Each row is the mean over severities 2, 3 and 5 (and corruption seeds). The CI
column is the mean of each run's paired-bootstrap 95% bounds.

| Corruption | Unimodal model | Unimodal macro-F1 drop | E2-8 drop | Difference (95% CI) |
|---|---|---|---|---|
| image: brightness_decrease | E0 | 0.048 | 0.016 | 0.032 (0.020 to 0.044) |
| image: brightness_increase | E0 | 0.012 | 0.006 | 0.006 (0.000 to 0.013) |
| image: contrast | E0 | 0.482 | 0.187 | 0.296 (0.271 to 0.318) |
| image: defocus_blur | E0 | 0.904 | 0.407 | 0.497 (0.479 to 0.512) |
| image: gaussian_noise | E0 | 0.862 | 0.490 | 0.372 (0.352 to 0.389) |
| image: jpeg_compression | E0 | 0.449 | 0.167 | 0.283 (0.259 to 0.309) |
| image: motion_blur | E0 | 0.569 | 0.216 | 0.354 (0.327 to 0.384) |
| iot: drift | E1 | 0.822 | 0.583 | 0.239 (0.217 to 0.256) |
| iot: dropout | E1 | 0.580 | 0.175 | 0.405 (0.378 to 0.430) |
| iot: sensor_noise | E1 | 0.476 | 0.211 | 0.265 (0.243 to 0.289) |

Fusion loses less than either single-modality model under every corruption.
Given the audit above, this is consistent with genuine complementarity and with
each branch falling back on session identity. The grouped split is what tells
the two apart. Full study:
[`THESIS_STYLE_ROBUSTNESS_REPORT.md`](corruption_study/results/THESIS_STYLE_ROBUSTNESS_REPORT.md).

## Reproduce

Python 3.12.

```bash
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu128
# CPU only: install torch/torchvision from download.pytorch.org/whl/cpu, then the
# remaining lines of requirements.txt
python -m pytest tests -q
python scripts/make_tables.py
python scripts/session_audit.py overlap audit/session_keys.csv Data
```

Those need no dataset. To retrain or re-evaluate, download the DACON images and
sensor logs into `Data/train`, `Data/val` and `Data/test`, and get the model
checkpoints and per-sample predictions from this repository's GitHub Release.
The pipeline order is in [`RUN_COMMANDS.txt`](RUN_COMMANDS.txt): E1 sensor
features, E0 and E1 training, E2 embedding extraction and training, then the E3
heads. It records the Windows commands and `scripts/thesis.ps1` wrapper the runs
used. The sensor-feature CSVs are not in this repository, so step 1
(`e1_iot_only/scripts/extract_iot_features.py`) must be run first. To rebuild
the session keys from raw data:

```bash
python scripts/session_audit.py build Data audit/session_keys.csv
```

## Repository layout

```text
Data/                   split manifests: image id + label (no images or sensor values)
audit/                  sensor-log session key per sample
common/                 shared E1 encoder definition and evaluation helpers
e0_image_only/          E0 MobileNetV3-Large image baseline
e1_iot_only/            E1 sensor-feature MLP and feature extraction
e2_multimodal_fusion/   E2 frozen-encoder fusion
e2_canonical_128_25/    wide (128 -> 25) fusion variant, exploratory
e3_quantum_fusion/      VQC layer and parameter-matched heads (E3-4)
e3_bottleneck_sweep/    4- vs 8-dimension bottleneck sweep and IoT robustness checks
e3_early_rescue/        early/severe-stage rescue-loss experiments
e3_beat_e2_attack/      targeted E3-8 variants (superseded)
corruption_study/       corruption generators, evaluation, bootstrap statistics, plots
prototypes/             early team prototypes (see below)
docs/by_stage/          thesis notes by stage; INDEX.md is the entry point
scripts/                make_tables.py, session_audit.py, thesis.ps1
tests/                  pytest suite (no data or GPU needed)
```
